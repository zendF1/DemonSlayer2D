# Phase 4a Maps, Portals and Zone Switching Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Five maps (the Ubuyashiki town and four training maps for levels 1–20) joined by portals. Walking into a portal moves the character to the next map with its HP, MP, items, Xu and cooldowns intact; the HUD's map label opens a zone list to switch khu in place; death respawns at the nearest respawn point of the same map. Maps are generated by a script.

**Architecture:**
- `tools/mapgen.py` declares every map with rectangles and writes `maps/*.json`; `mapdata` parses the new fields (`min_zones`, `portals`, `spawn_points[].respawn`), checks reachability per map and portal targets across maps. `monster_stats.py` adds six normal kinds.
- `World.Transfer` is the one path for moving a player between zones: resolve the destination, reserve a seat in the destination zone, ask the current zone to depart (the zone runs a check closure on the live player, removes it, queues a save at the destination and returns a handoff `PlayerInfo`), then join the destination zone, which sends a fresh `EnterWorldResp` with the request's seq. The gateway swaps `c.member`.
- Worlds keep `min_zones` zones open per map; `ZoneListReq` is answered by the world from zone counts.
- Protocol 9: `UsePortalReq`, `ChangeZoneReq`, `ZoneListReq/Resp`, `Cooldown`, `EnterWorldResp.cooldowns`, `ZONE_NOT_FOUND`.
- The client reloads the World scene from the new `EnterWorldResp`; `Net.request(…, hold_on_reply)` holds pushes from the reply on.

**Tech stack:** Go, protobuf (buf), Postgres, Python 3 scripts; Godot 4.7.2, GDScript, godobuf.

**Spec:** [docs/superpowers/specs/2026-11-20-giai-doan-4a-nhieu-map-cong-khu-design.md](../specs/2026-11-20-giai-doan-4a-nhieu-map-cong-khu-design.md). Section references below (§n) point to it.

**Prerequisite:** phases 3a, 3b and 3c are fully implemented (protocol 8, migrations up to 00006, `internal/items`, inventory and Xu in `PlayerInfo`). Start from a server HEAD that contains them.

**Plan format (from the user):** interfaces, behaviour, test cases and TODOs only. Write the code at implementation time; nothing here is meant to be copied.

**Commit rules (from the user):** commit and push after every task with a clear message; **no** `Co-Authored-By` or other trailer; `git add` specific paths only (never `-a`), because other agents may edit the same tree; `git pull --rebase` before `git push`, never force push. Server tasks commit in this repo, client tasks in `../DemonSlayer2DGame`.

**Test rules:** Go tests with `-race` (DB/e2e: `TEST_DATABASE_URL='postgres://ds:ds@localhost:5433/ds_test?sslmode=disable' go test -race ./...`); 1–2 test files per package with `// ______________________TEST X_____________________` sections (GDScript `# ____...`); a fix comes with a test that fails on the old code; before committing Go: `staticcheck ./...`, `go vet ./...`, `graphify update .` (skip if graphify is missing). Every commit leaves `go build ./...` and `make test` green. Client: `tests/run.sh`.

### Task 5: Server — zone departure and handoff

**Files:** `internal/zone/transfer.go` (new), `internal/zone/zone.go`, `internal/zone/combat.go`, `internal/zone/skill.go`, tests.

**Interface:**
- `type Place struct { MapID string; Pos Vec2 }` — where a departing player is saved.
- `type Departure struct { Check func(d *Departing) pb.ErrorCode; To Place; KeepPos bool; ZoneChange bool }` — `Check` runs on the zone goroutine; `KeepPos` saves and hands over the current position instead of `To.Pos` (zone change). `Departing` is a small zone-owned handle over the live player with only what 4a needs: `Dead() bool`, `Pos() Vec2`, `ZoneChangeReady() bool`. Phase 4b adds cost hooks (`TakeXu`, `TakeItem`) that apply only when `Check` returns no error.
- `func (z *Zone) Depart(ctx context.Context, id uint64, d Departure) (info PlayerInfo, saved <-chan error, code pb.ErrorCode, err error)` — queues a `departCmd` and waits like `Join`; `err` is `ErrZoneClosed` when the zone stopped; `code` non-zero means refused and nothing changed.
- `PlayerInfo` gains `Cooldowns map[string]time.Duration` (keys: skill ids, `"slash"`, `"zone_change"`).
- `func (z *Zone) handoff(p *player) PlayerInfo` — live state (§3.2.1), HP/MP as they are (never −1), deep copies.
- `func (z *Zone) cooldownsOf(p *player) map[string]time.Duration` and the join side that turns them back into ticks (`ticks`, rounding up; expired entries dropped). `player` gains `zoneReady uint32`.
- `join` fills `EnterWorldResp.cooldowns` from the player's remaining cooldowns (sorted by key) — empty on a fresh login.

**Behaviour (§3.2):** in `drain`, a `departCmd` for a player no longer in the zone (evicted meanwhile) answers the sentinel `ErrNotInZone`; the world returns it and the gateway treats the membership as lost (the conn is already being kicked). Otherwise run `Check`; on a non-zero code reply with it and change nothing. On success: build the handoff, remove the player from the cells, `players`, `setCount`, clear monster targets/attackers pointing at it (as `killPlayer` does), drop its pending attack/cast, drop the 3c pending refine, queue `saver.Save` of `state(p)` with `MapID`/`X`/`Y` from `To`, and reply. Phase 3 player fields (Xu, inventory, ground items stay) go into the handoff via the same helpers `state` uses.

### Task 6: Server — world: minimum zones, Transfer, zone list

**Files:** `internal/world/world.go`, `internal/world/world_test.go`.

**Interface:**
- `zone.Area`/world keep `minZones` per map from `mapdata.Map.MinZones`.
- `type TransferKind int` (`TransferPortal`, `TransferZone`; 4b adds `TransferScroll`, `TransferTravel`); `type TransferReq struct { Kind TransferKind; PortalID string; Zone int; RespSeq uint32 }`.
- `type TransferError struct { Code pb.ErrorCode }` (implements `error`) for refusals the gateway answers with `ErrorResp`.
- `func (w *World) Transfer(ctx context.Context, m *Membership, req TransferReq) (*Membership, <-chan error, error)` — §3.2 steps; the channel is the departure save, non-nil only when the player has left its zone but did not join a new one (world stopped).
- `func (w *World) reserveIn(mapID string, prefer int, exact bool) (*slot, pb.ErrorCode)` — `exact` for zone change (`ZONE_NOT_FOUND`, `ZONE_FULL`), else prefer the same number then fall back to `reserve`.
- `func (w *World) Zones(mapID string) []ZoneInfo` (`ZoneInfo{No, Players int}`) and `Capacity() int`.

**Behaviour:**
- `Start` opens `min_zones` zones per map; `closeIdle` skips slots with `no ≤ minZones`.
- Portal: unknown id in `m.MapID` → `TransferError{BAD_REQUEST}`; destination `Place{to_map, Spawns[to_spawn]}`; `reserveIn(to_map, m.ZoneNo, false)`; check closure: `DEAD`, then `RectDistance(pos, rect) > 1` → `OUT_OF_RANGE`.
