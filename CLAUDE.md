# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Go game server for DemonSlayer2D, a 2D online RPG. The Godot client is in a separate repo and consumes `proto/` and `maps/`, so treat changes to those as client-facing. Design docs (`docs/`) are in Vietnamese; code, comments and commit messages are in English.

## Commands

```bash
make db-up     # Postgres on localhost:5433
make run       # server on :8080 (/ws, /healthz)
make test      # unit tests; DB tests skip
make test-db   # all tests incl. DB and e2e
make proto     # regenerate internal/pb (never edit it by hand)
staticcheck ./...

# single test
TEST_DATABASE_URL='postgres://ds:ds@localhost:5433/ds_test?sslmode=disable' go test -race -run TestName ./internal/world/
```

Config comes only from environment variables (see `README.md`). The Makefile also loads `.env`. To override for one run: `make run VAR=value`.

## Code map (graphify)

`graphify-out/graph.json` maps the code's functions, types, calls and modules. It covers code only: `.graphifyignore` excludes `docs/`, `*.md` and the generated `internal/pb/`. The graph is local and git-ignored.

- **Use the graph before grep or reading files.** For questions about the code, run `graphify query "<question>"`, `graphify explain "<symbol>"` or `graphify path "<A>" "<B>"`. Then read only the lines the graph points to.
- **Overview:** `graphify-out/GRAPH_REPORT.md` lists the communities and god nodes. Read it only for a broad overview.
- **Keeping it current:** git hooks rebuild the graph after commit, checkout and merge. After editing code but before committing, run `graphify update .` (AST only, no cost). After deleting code, run `graphify update . --force`.
- **If `graphify-out/` is missing** (fresh clone), run `graphify update .` and then `graphify hook install`.

## Invariants (not visible in the graph)

- A new login must wait until the previous session has finished saving (`world.Takeover`, serialised per account).
- Zone tick order is fixed: `newDay → drain → runImpacts → resolveAttacks → movePlayers → thinkMonsters → runSpawnTimers → runGroundTimers → runPlayerTimers → syncView`. Attacks are decided at press and damage lands at its impact tick in `runImpacts`, where monsters die and drop. Item commands run in `drain`. `newDay` checks the day once a second.
- Zone state is touched only by that zone's goroutine. Zones never write to the DB; they pass saves to `saver`.
- On shutdown, the saver flushes under its own timeout, even when the gateway step has timed out.
- Rate limits use `Limiter.Take` and `Refund`; never split checking and recording into separate calls.
- Game data is generated; edit the script in `docs/balance/`, not the JSON: `data/monsters.json` from `monster_stats.py`, `data/skills.json` from `skill_stats.py`, `data/exp.json` and `exp-table.csv` from `exp_table.py`, `data/items.json` from `item_stats.py`, `data/quests.json` from `quest_data.py` (rerun it when `exp.json` or the monster regions in `maps/` change). Go tests compare each JSON with its script's output.
- Maps (`maps/*.json`) are generated by `tools/mapgen.py`; edit the script and run `python3 tools/mapgen.py --write`, never hand-edit the JSON. A `mapdata` test runs `--check` and checks that every map is reachable from `kumotori_1` and every portal has a reverse.
- Every move between zones (portal, zone change, return scroll, carriage) goes through `World.Transfer`: reserve a seat in the target zone, have the current zone depart the player in `drain` (the transfer's check runs on the live player; then the zone removes it and queues a save at the destination), then join the target zone with the in-memory handoff `PlayerInfo`, cooldowns included. A scroll or carriage cost is applied in the departing zone after the check passes and before the handoff and save. Never reload the character from the DB for a transfer. The gateway swaps `c.member` on the connection goroutine.
- A map always keeps zones 1 to `min_zones` open; `closeIdle` closes only empty zones above that.
- Renaming an item code or shrinking `bag_size` in `item_stats.py` deletes the affected stored items at the next login (`world.knownItems` drops them); such a change needs a data migration.
- Monster EXP is `HP × r(L)`, so the level-up table depends on monster HP. When monster HP changes, run `monster_stats.py` and `exp_table.py` together. `item_stats.py` and `monster_stats.py` (its reference gear) both read `equipment_balance.py`, so when gear stats change, run `item_stats.py`, `monster_stats.py` and `exp_table.py`.
- Combat formulas live only in `internal/combat`. That includes `combat.ScalePct` (percent scaling, rounds up).
- Monster kinds carry `hp_pct`, `attack_pct` (50-200) and `damage_type` (`phys`/`magic`), all required. Every zone read of a level row goes through `statsOf` (spawn.go): HP and EXP scale by `hp_pct`, attack by `attack_pct`, defense never; a magic kind hits the player's magic defense (`monsterHitDefense`). Never read `z.area.Levels` directly.
- Player-versus-player rules live only in `combat.PvPAllowed` and the press-time check (`foeOf`/`checkPlayerTarget`/`pvpCheck`: INVALID_TARGET, then map `PvP`, then safe zone, then the PK table); a PvP hit is fixed at the press and lands in `runImpacts` even if the target has since entered a safe zone or turned PK off. The PK EXP penalty is charged only in `killPlayer`, by the killing blow (by a player, area `PkPenalty`, victim PK on). PK-off lock (`pvpLockSec` 10) starts on both sides when a PvP hit is accepted at the press (`hitOn`, to due + 10 s) and is refreshed, never shortened, when it lands; it travels in the handoff as `pvp_combat`, refuses `LeaveWorldReq` (`IN_PVP_COMBAT`, `Zone.Quit`), and a player removed while locked (disconnect, kick) has it remembered by the world (`pvpLocks`, wall clock, under `w.mu`) and given back on its next `Enter`; `pk_on` is stored (migration `00008`). `LookChange` carries the whole look at the end of the tick, recorded by entity id.
- Enhancement attempts, their costs, the hidden pity and the regen milestones live only in `internal/items`; the enhancement table, the regen milestones and `charm_protect` come from `item_stats.py`. Pity is stored per item (`character_items.pity`) and never sent to clients. The zone enhances only within 3.5 tiles of a blacksmith NPC (`NPC_TOO_FAR`; `NOT_IN_SAFE_ZONE` is unused since protocol 10), regenerates once a second in `runPlayerTimers` and sends the worn weapon's enhance level as `weapon_enhance`/`LookChange`.
- Resonance (which hidden lines are lit), gem stats, punching, socketing, unsocketing and the refine roll live only in `internal/items`; the resonance table, the socket and refine costs and the 15 gems come from `item_stats.py`. Holes are stored as `character_items.gems` (one entry per hole, `""` for an empty one). The zone forges only within 3.5 tiles of a blacksmith NPC (`NPC_TOO_FAR`). A refine result waits in zone memory only (`player.refine`) and is dropped by leaving and by every item command except pickup, buy, use-item and the choice itself (`dropsRefine`); a sale and the stash deposit, withdraw and sort drop it themselves, only when they succeed; stash open and expand never drop it. The client computes the lit lines from the same table for display only; the server's stats are authoritative.
- Lượng, the stash size and the stash items belong to the account (migration `00007`), held and saved by the zone of the account's one in-world character. Every `CharState` the zone saves carries them (deep copy), because the saver coalesces per character, and the store writes them in the same transaction. Last writer wins, so the Takeover and leave-save ordering is what keeps them safe. Stash commands need the storage NPC within 3.5 tiles. The Lượng shop is `anywhere` (`BuyReq.shop_id`, empty `npc_id`). Respawn in place costs 1 Lượng and saves at once; village and auto respawn stay free. `devitem`, `devchar` and `devquest` need every character of the account offline.
- NPCs are map data (`maps/*.json`, from `tools/mapgen.py`), not entities: the zone checks distance to the listed NPC (`npcRange` 3.0 + `npcSlack` 0.5). Shops and prices (buy, sell, potion effects, `use_cooldown_sec`) live in `items.json`, from `item_stats.py`; the map-wide carriage prices come from `mapgen.py`.
- Potion use does not save at once (the periodic save covers it). The cooldown is per group (`hp`, `mp`) and travels in the handoff as `potion_<group>` cooldown keys; it is never stored.
- EXP is paid per hit by damage share (`internal/zone/progression.go`), only when player and monster are within 10 levels. Teammates in the same zone get 5% of each payment on top (`payPartyBonus`, `combat.PartyBonus` with a per-player carry in hundredths; monster within 10 levels of the teammate, dead teammates included, no chaining, not counted against the monster). Xu and drops go to the killer only: Xu straight into the wallet, items on the ground, seen and picked up only by the killer's character, gone after 60 s.
- Parties live only in `internal/party`: in memory, one mutex, never saved, never calling into world or zone; it pushes invites, states and notices into member outboxes (non-blocking `Send`; a push a full outbox refuses kicks the connection with `SLOW_CONSUMER`, since party pushes have no resync). Each session has one `*atomic.Uint64` party-id cell that the party service writes and zones only `Load`, never store; it rides the handoff. The world registers a player at `Enter`, unregisters in `Membership.Leave` (and in `Quit` only after the zone accepts, so the 5a `IN_PVP_COMBAT` refusal keeps the party), calls `Moved` after a `Transfer` and `Leveled` from `gainExp`. Teammates cannot hit each other: `pvpCheck` returns `PK_FORBIDDEN` when `sameParty`.
- Quests (phase 6b): the zone holds the log as `quest.Log` (a map), accepts, credits and turns in; the world's `knownQuests` at `Enter` drops unknown ids, clamps progress and resets the main-line day. Credit goes to the killer only, at loot in `runImpacts`, and is never shared through a party. `QuestProgress` is flushed in `syncView` after `WorldTick`/`DeathNotice` and before `SelfStats`. Accept and turn-in save at once, progress with the periodic save. Turn-in is all-or-nothing: `BAG_FULL` pays nothing. Quest commands keep a pending refine. A quest item is a counter, not a bag item.
- Skill books: the first learn of a skill takes `book_<class>_<n>` from the bag (the lowest slot) unless the learn level is at most `p.bookWaiver` (`characters.skill_book_waiver`, carried through the zone so saves keep it). `NO_SKILL_BOOK` is checked after `NOT_ENOUGH_POINTS`.
- Daily quests (phase 6d): the quest day changes at 00:00 UTC+7 (`quest.Day`). Zones use `Config.Now` only for the quest day; `join` syncs the zone day from it before pruning stale dailies, and `newDay` prunes for players already in the zone. Midnight prunes do not save at once. The `QuestLog` push goes out in `syncView` before `QuestProgress`. Daily rewards scale with level (`quest.DailyReward`). `kill_any` and `collect_any` credit only a monster within ±10 levels of the killer. Enhance credit counts the attempts that actually ran, only when the command succeeds. `devquest -day-offset` writes a daily's day relative to today.
- Auto-combat (phase 6c) runs on the client and sends only ordinary requests (attack, cast, use item, pickup, move; targeting stays on the client) within the usual rate limits; the server has no auto state and protocol and data are unchanged. Its rules live in the client's `core/auto_play.gd`, settings in `core/auto_settings.gd`; `screens/world.gd` only wires them.
- Pathfinding and click-to-move are client-side (phase 6a, protocol unchanged): the server accepts only `MoveInput` directions and has no go-to-point command.
- Proto names must stay valid in GDScript (no field named `message` or `class`, no message named `Error`) because the client generates code with godobuf.
- godobuf's tokenizer misreads a proto comment with two apostrophes on one line (for example "the gem's level is above the item's tier"). The client's `tools/gen_proto.sh` now strips `//` comments before generating, but still avoid such comments.

## Conventions

- Run tests with `-race`. A fix comes with a test that fails on the old code.
- Keep one or two test files per package (for example `internal/auth/auth_test.go`), not one per source file. Split sections with a comment line such as `// ______________________TEST LIMITER_____________________`.
- Commit and push after each piece of work, with no signature or `Co-Authored-By` trailer.
